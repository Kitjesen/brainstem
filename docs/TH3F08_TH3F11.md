# TH3F08 / TH3F11 三档体高策略使用说明

更新：2026-11-09。这里提供当前两版策略的 ONNX、TorchScript、观测/动作适配器和接口契约。**模型可以用于离线推理和控制器接入；08/11 板端服务适配尚未完成构建与接口验收，也尚未切换到实机服务。**

## 选择哪一版

| 策略 | 来源 checkpoint | 低档 | 中档 | 正常档 | 选择说明 |
|---|---|---:|---:|---:|---|
| TH3F08 | model_5993 | 0.15 m | 0.30 m | 0.4405706826868142 m | 当前优先选择 |
| TH3F11 | model_6492 | 0.10 m | 0.30 m | 0.4405706826868142 m | 从 08 微调，低档降至 0.10 m |

这是一个策略接收三档高度命令，并在每一档执行前后移动、横移、转向、混合运动和停车。正常档数值来自 W5 默认姿态的几何计算，不能写成 0.42 m。三档之间的过渡由策略执行，不代表任意连续高度已得到验收。

模型目录：

```text
model/TH3F08/               model/TH3F11/
  policy.onnx                policy.onnx
  policy.pt                  policy.pt
  inference_contract.json    inference_contract.json
  w5_inference.py             w5_inference.py
  export_report.json          export_report.json
```

`policy.pt` 是 TorchScript 推理模型；完整训练 checkpoint 和优化器保留在原归档，本目录不包含它们。`export_report.json` 是原始导出报告；`inference_contract.json` 中的 `checkpoint_file` 是来源标识，不是下载后运行所需文件。两版文件须成套使用。

## 下载与一次无硬件推理

```bash
git clone --branch bodyheightctrl --single-branch https://github.com/Kitjesen/brainstem.git
cd brainstem
python -m venv .venv
# Linux / macOS
source .venv/bin/activate
# Windows PowerShell 使用：.venv\Scripts\Activate.ps1
python -m pip install numpy onnxruntime
```

将下面代码保存为仓库根目录下的 `try_th3.py`，执行 `python try_th3.py`。切换版本只改 `MODEL_ID`。示例用合成传感器值检查接口，**不连接电机，不模拟机器人运动，不评价控制性能**。

```python
from pathlib import Path
import importlib.util
import json
import numpy as np
import onnxruntime as ort

MODEL_ID = "TH3F08"  # 或 TH3F11
model_dir = Path("model") / MODEL_ID
contract = json.loads((model_dir / "inference_contract.json").read_text(encoding="utf-8"))
spec = importlib.util.spec_from_file_location("th3_adapter", model_dir / "w5_inference.py")
adapter = importlib.util.module_from_spec(spec)
spec.loader.exec_module(adapter)
session = ort.InferenceSession(str(model_dir / "policy.onnx"), providers=["CPUExecutionProvider"])
assert session.get_inputs()[0].name == "observation"
assert session.get_inputs()[0].shape[-1] == 58
assert session.get_outputs()[0].name == "action"
assert session.get_outputs()[0].shape[-1] == 16

# 每次真实策略 reset 时置零；普通换档不清零。
previous_raw_action = np.zeros(16, dtype=np.float32)

def policy_step(omega_body, gravity_body, command, q, dq):
    global previous_raw_action
    obs = adapter.observation(omega_body, gravity_body, command, q, dq, previous_raw_action)
    raw = session.run(["action"], {"observation": obs})[0][0]
    leg_position_rad, wheel_velocity_rad_s = adapter.targets(raw)
    previous_raw_action = raw.copy()  # 保存原始输出，不保存限幅/混合后的目标
    return leg_position_rad, wheel_velocity_rad_s

for height in contract["height_commands_m"]:
    legs, wheels = policy_step(
        np.zeros(3), [0, 0, -1], [0, 0, 0, height],
        adapter.DEFAULT_Q.copy(), np.zeros(16),
    )
    print(MODEL_ID, "height", height, "leg targets(rad)", legs, "wheel targets(rad/s)", wheels)
```

TorchScript 使用相同的 `adapter.observation()` 和 `adapter.targets()`；用 `torch.jit.load("model/TH3F08/policy.pt", map_location="cpu").eval()` 加载，并在 `torch.no_grad()` 下输入 `torch.from_numpy(obs)`。不要将训练 checkpoint 直接当作 TorchScript 加载。

## 控制周期和命令

策略周期是 **20 ms / 50 Hz**。每周期读取真实传感器、组装观测、推理、解码目标，再交给已有控制器执行。示例中的固定传感器只供接口检查，不能用作实机闭环输入。

- 命令顺序：`[vx, vy, wz, height]`，单位依次为 m/s、m/s、rad/s、m。
- 停车保持：`[0, 0, 0, 当前档高度]`。需要继续运行策略闭环，不能停止推理后期望主动保持体高。
- 停车换档：只替换高度分量，前三项保持 0；不 reset，不清空动作历史。
- 运动换档：保留当前速度分量，只修改高度；不因为低档而额外关闭横移。
- 切换 08/11 是模型切换，不是普通高度换档。控制器需经过其既有受控切换流程，初始化新策略的历史，避免在活动输出中直接替换文件。

训练命令范围为 `vx ±2.5 m/s`、`vy ±1 m/s`、`wz ±1 rad/s`。这不等于已验收的实机速度范围；控制器应保留其实际限速和关节保护。

## 精确输入接口

ONNX 输入名 **`observation`**，float32 `[batch, 58]`；输出名 **`action`**，float32 `[batch, 16]`。单机器人使用 batch=1。网络为 58→512→256→128→16，ELU，无额外观测均值/方差归一化。61 维是训练 critic 的接口，不是部署输入。

| 观测索引（左闭右开） | 内容 | 缩放 |
|---|---|---:|
| 0:3 | 机身坐标系角速度，rad/s | ×0.25 |
| 3:6 | 单位重力在机身坐标系中的投影 | ×1 |
| 6:10 | `[vx, vy, wz, height]`，高度位于索引 **9** | ×1 |
| 10:26 | 关节位置减固定 W5 默认角；末四项轮位置强制为 0 | ×1 |
| 26:42 | 16 个关节的真实角速度，rad/s | ×0.05 |
| 42:58 | 上一周期的原始策略输出 | ×1 |

各项先转 float32，再逐项裁剪到 `[-100, 100]`，**然后缩放**。平放时投影重力约为 `[0, 0, -1]`；若 `R_world_from_body` 将机身向量转到世界系，计算为 `R_world_from_body.T @ [0,0,-1]`，不要输入带 9.81 的加速度向量。

关节顺序：FR 的 hip/thigh/calf，FL 的 hip/thigh/calf，RR 的 hip/thigh/calf，RL 的 hip/thigh/calf，最后 FR/FL/RR/RL 四个轮。关节位置为 rad，速度为 rad/s；需要先完成硬件关节正负号、编码器零位到此顺序的映射。

## 固定默认姿态与动作解码

| 腿 | Hip (rad) | Thigh (rad) | Calf (rad) |
|---|---:|---:|---:|
| FR | −0.12 | −0.93 | +1.96 |
| FL | +0.12 | +0.93 | −1.96 |
| RR | +0.12 | +0.93 | −1.96 |
| RL | −0.12 | −0.93 | +1.96 |

四个轮的默认位置槽为 0。**这组 DEFAULT_Q 在所有命令高度下保持不变**；训练中的随高度变化的软参考姿态不能替换这里的观测零位或 action offset。

```text
a = clip(raw_action, -100, 100)
12 腿关节目标角 = DEFAULT_Q[:12] + a[:12] * tile([0.125, 0.25, 0.25], 4)
4 轮目标角速度 = a[12:16] * 5.0
下一周期历史 = raw_action（未经目标限幅、入场混合或电机门控的输出）
```

策略输出不是 16 维力矩。训练/仿真的名义腿关节 PD 是 Kp=100、Kd=5，轮速度控制为 Kp=0、Kd=1；腿/轮名义力矩上限分别为 120/17 N·m，速度上限分别为 17.48/42.94 rad/s。这些是控制契约背景，不能据此跳过具体执行器的编码范围、实际限位和保护。

停车时仍保留模型给出的轮速度目标；不要在普通零速命令路径上用 `forceZeroWheelOnStop` 把策略轮输出强制清零。急停、失联、电机故障等原有停止保护仍须生效。

## 与本分支旧服务的区别

旧 H15/H18 把高度放在观测末尾，输入名分别为 `policy_obs` / `policy_history`；旧 single-frame V2 虽同为 58 维，输入名是 `obs`，默认角、档位和配置也不同。因此 **08/11 不能直接替换旧 V2/H15/H18 的 ONNX 文件**。

本次新增的是模型与接入资料。现有 `scripts/bodyheight_service.sh start v2|h15|h18` 和旧 gRPC 使用说明仍属于旧控制器；没有可直接用于 08/11 的已验收启动命令。不要把旧服务的连续高度范围或默认高度用于这两版。

二号机的新版 Dart 适配已完成部分观测/历史、profile 和真实 ONNX 对照；但源码所在板子目前无法连接，最终 CLI/接口测试、ARM64 构建和服务切换尚未完成。该未完成适配不在本次模型发布中；本文不提供未经验证的 `systemctl` 启动或电机使能命令。

## 验证依据和使用边界

原始导出记录：

| 策略 | 输入组数 | TorchScript 最大绝对差 | ONNX 最大绝对差 | 联合容差 |
|---|---:|---:|---:|---|
| TH3F08 | 1057 | 0 | 8.58306884765625e-6 | atol=rtol=1e-5 |
| TH3F11 | 1057 | 0 | 5.7220458984375e-6 | atol=rtol=1e-5 |

另有原有 10 帧双 MuJoCo 实现的 state/CSV 与真实子步力矩一致性证据。这是两种 MuJoCo 实现之间的核对，不是 Isaac→MuJoCo 或实机一致性证明。此次上传不重训、不重新导出或修改权重。

2026-11-09 发布前，使用待上传文件对每个模型检查了 12 帧独立输入、12 帧连续动作历史输入，并分别运行了上面的 Python 示例，均通过。ONNX 与 TorchScript 的最大绝对差为 1.9073486328125e-5，满足 `abs(a-b) <= 1e-5 + 1e-5*abs(b)` 的联合容差；该输入集与原 1057 组导出测试不同。详见[发布核验记录](validation/th3-policy-publication-20261109.json)。

08 是此前选择的候选，但仍有停车漂移，六条 112 秒停车对照的平均最终位移约 0.953 m；高速反向切换曾出现超过名义轮速上限的仿真输出。11 的现有完整运动资料仅覆盖 0 kg、单 seed 的四段演示；两版均不能据此宣称完成全载荷 306 场验收或实机验收。更详细的限制保留在各自 `inference_contract.json` 的 `known_limits`。
